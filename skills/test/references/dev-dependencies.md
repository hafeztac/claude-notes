# Dev Dependencies

Every package a test imports must be declared in the repo's dev-dependency location. Find the
existing one and add to it — never introduce a second, competing mechanism.

## Find it

```bash
ls pyproject.toml requirements*.txt dev-requirements.txt Pipfile setup.py setup.cfg tox.ini 2>/dev/null
grep -rn "pytest" pyproject.toml requirements*.txt Pipfile setup.py 2>/dev/null
ls requirements/ 2>/dev/null      # some repos split: base.txt, dev.txt, test.txt
```

Precedence when several exist: whichever CI actually installs. Check the workflow file:

```bash
grep -rn "pip install\|uv sync\|poetry install\|pdm install" .github/workflows/ Makefile 2>/dev/null
```

## PEP 735 dependency groups (`pyproject.toml`) — modern default

```toml
[dependency-groups]
dev = [
    "pytest>=8.0",
    "pytest-cov>=5.0",
]
test = [
    "pytest-playwright>=0.5",
]
```

Install: `uv sync --group dev` or `pip install --group dev` (pip ≥ 25.1).

## Optional dependencies (`pyproject.toml`) — widely supported

```toml
[project.optional-dependencies]
dev = [
    "pytest>=8.0",
    "pytest-cov>=5.0",
    "pytest-playwright>=0.5",
]
```

Install: `pip install -e ".[dev]"`.

## Poetry

```toml
[tool.poetry.group.dev.dependencies]
pytest = "^8.0"
pytest-cov = "^5.0"
```

Install: `poetry install --with dev`. Prefer `poetry add --group dev pytest` so the lockfile
updates; if you hand-edit, run `poetry lock --no-update` after.

## PDM / Hatch

```toml
[tool.pdm.dev-dependencies]
test = ["pytest>=8.0"]
```

```toml
[tool.hatch.envs.test]
dependencies = ["pytest>=8.0"]
```

## requirements files

```
# requirements-dev.txt
-r requirements.txt
pytest>=8.0,<9
pytest-cov>=5.0
```

Keep the `-r requirements.txt` line at the top so one install gets both. If the repo uses
`pip-tools`, edit `requirements-dev.in` and regenerate:

```bash
pip-compile requirements-dev.in
```

Never hand-edit a compiled `.txt` that says "generated by pip-compile" at the top.

## Pipenv

```bash
pipenv install --dev pytest
```

## Baseline package set

Add only what the tests you are writing actually import. Pin a lower bound, not an exact
version, unless the repo pins exactly throughout.

**Always**

| Package | For |
|---|---|
| `pytest` | the runner |
| `pytest-cov` | coverage, when the repo reports it |

**Commonly needed**

| Package | For |
|---|---|
| `pytest-asyncio` | `async def` tests |
| `freezegun` | deterministic time |
| `factory-boy` | data builders with relationships |
| `pytest-randomly` | shuffles order; catches inter-test leakage |
| `pytest-xdist` | `-n auto` parallelism once the suite is slow |

**By stack**

| Package | For |
|---|---|
| `httpx` | testing an ASGI app without a live server |
| `respx` | stubbing httpx calls |
| `responses` | stubbing `requests` calls |
| `pytest-django` | Django `db` fixtures, settings handling |
| `pytest-flask` | Flask app/client fixtures |
| `testcontainers[postgres]` | a real database in CI without a service block |
| `pytest-postgresql` | lighter alternative for a per-run Postgres |
| `pytest-playwright` | the browser tier |
| `axe-playwright-python` | accessibility assertions |
| `selenium` + `pytest-selenium` | only if the repo already standardizes on Selenium |

## After editing

1. Install: `pip install -e ".[dev]"` / `uv sync --group dev` / `pip install -r requirements-dev.txt`.
2. Browsers, if e2e: `playwright install chromium` (`--with-deps` in CI).
3. Confirm collection works before writing tests:
   ```bash
   python -m pytest --collect-only -q
   ```
4. If a lockfile exists (`poetry.lock`, `uv.lock`, `Pipfile.lock`), regenerate it and say so —
   a dependency edit that skips the lockfile breaks CI, not your machine.
5. If CI installs dev deps by an explicit list rather than a group, update the workflow too.
